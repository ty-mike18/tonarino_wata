# つまずいたときの対処集

症状から探してください。

---

## ビルド・実行まわり

### 画面が真っ白のまま何も出ない

`www/` の中身が古いか、同期できていません。

```bash
cd ios
npm run build
npx cap sync ios
```

そのうえで Xcode で **Product → Clean Build Folder**（⇧⌘K）してから ▶ を押します。

それでも直らない場合は、Safari の Web インスペクタ（マニュアル STEP 8-3）で
コンソールにエラーが出ていないか確認してください。

---

### `npx cap add ios` が `pod install` で失敗する

CocoaPods のリポジトリ情報が古いことがほとんどです。

```bash
cd ios/App
pod repo update
pod install
cd ..
```

`Podfile.lock` が壊れている場合は、いったん消してやり直します。

```bash
cd ios/App
rm -rf Pods Podfile.lock
pod install
```

---

### `xcodebuild: error: ... requires a development team`

Xcode の **Signing & Capabilities** で Team が選ばれていません。

1. Xcode メニュー → **Settings** → **Accounts** → **＋** で Apple ID を追加
2. プロジェクト → TARGETS の **App** → **Signing & Capabilities**
3. **Automatically manage signing** にチェック、**Team** を選択

---

### `Command PhaseScriptExecution failed` と出る

`ios/www/` が存在しないときによく出ます。`npm run build` を先に実行してください。

---

### Archive がグレーで押せない

画面上部の実行先が **シミュレータ**になっています。
**Any iOS Device (arm64)** に変更してください。

---

## 実機まわり

### iPhone が Xcode の一覧に出てこない

1. ケーブルを挿し直し、iPhone 側で「信頼」を押す
2. iPhone の **設定 → プライバシーとセキュリティ → デベロッパモード** を **オン**（再起動が必要）
3. Xcode メニュー → **Window** → **Devices and Simulators** で認識されているか確認

---

### 実機にインストールできたが「信頼されていないデベロッパ」と出て起動しない

iPhone の **設定 → 一般 → VPN とデバイス管理 → デベロッパApp** から
自分の Apple ID を選び、**信頼** を押してください。

---

## 通知・バッジまわり

### 通知が届かない

順に確認してください。

1. **記録タブのリマインダーが ON になっているか**
2. **iPhone の 設定 → となりの栄養士 → 通知 が許可になっているか**
   （一度「許可しない」を押すと、以後アプリからは聞けません。ここで手動で ON にします）
3. **設定時刻が「これから来る時刻」になっているか**
   すでに過ぎた時刻には通知を予約しません（仕様）
4. **その日にもう記録を入力していないか**
   記録済みの日は通知しません（仕様）
5. **集中モード / おやすみモード** が有効になっていないか

Web インスペクタで次を実行すると、予約状況を直接見られます。

```js
await Capacitor.Plugins.LocalNotifications.getPending();
```

`id` が `4200` 〜 `4213` の通知が並んでいれば予約できています。

---

### アイコンにバッジが付かない

バッジ用のプラグインが入っていない可能性があります。

```js
Object.keys(Capacitor.Plugins);
```

一覧に `Badge` が無ければ、次を実行してください。

```bash
cd ios
npm install @capawesome/capacitor-badge
npx cap sync ios
```

バッジの表示には **通知の許可**（バッジを含む）が必要です。通知を許可していない場合は付きません。

なお、バッジが出なくても記録・通知・書き出しなど他の機能には影響しません。

---

## データまわり

### CSV の書き出しで何も起きない

`@capacitor/filesystem` と `@capacitor/share` が入っているか確認します。

```bash
cd ios
npm list @capacitor/filesystem @capacitor/share
npx cap sync ios
```

Web インスペクタのコンソールに `[tonari-native] share failed` と出ていれば、
そのエラーメッセージが原因です。

---

### 記録が消えてしまった

このアプリでは、記録は次の2か所に入っています。

1. **localStorage**（本体）
2. **アプリ内の自動バックアップ**（`Library/tonari-backup.json`）

localStorage が空になっていれば、**次回起動時に自動でバックアップから書き戻します**
（1回だけ画面が再読み込みされます）。

両方失われるのは、**アプリを削除したとき**だけです。
その場合は、経過タブから書き出しておいた CSV で復元してください
（プロフィールと約束の履歴は CSV に含まれないため、初回アセスメントは再入力になります）。

---

### アプリを更新したら記録が消えないか心配

App Store 経由の更新では、アプリのデータ領域はそのまま残ります。記録は消えません。
消えるのは「アプリを削除して入れ直したとき」だけです。

---

## 審査まわり

### 「4.2 Minimum Functionality」で却下された

[`ios/appstore/04_審査への注記.md`](../appstore/04_審査への注記.md) の
**「4.2 で却下されたときの返答文例」** をそのまま Resolution Center に貼ってください。

あわせて、実機で通知が届いている様子を **動画（30秒程度）** で撮って添付すると、
一度で通ることが多いです。

---

### 「アプリ名がすでに使われています」と出る

App Store Connect の「名前」は世界で一意です。次のように少し足してください。

- `となりの栄養士 - 食事バランス記録`
- `となりの栄養士｜毎日の食事と睡眠`

アプリ本体のホーム画面表示名（`CFBundleDisplayName`）は「となりの栄養士」のままで構いません。

---

## それでも解決しないとき

Web インスペクタのコンソールで次を実行し、出力を控えてから調べると原因を絞りやすくなります。

```js
window.__tonariDebug = true;
console.log(Capacitor.getPlatform(), Object.keys(Capacitor.Plugins));
console.log(JSON.parse(localStorage.getItem("tonari-data")));
```
